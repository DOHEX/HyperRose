## 帧格式

与 BudsFeel MK2 相同：

```
命令:  FF SEQ CMD [TYPE] [VALUE…] CK AA     （手机 → 耳机）
响应:  DD SEQ TYPE [VALUE…]    CK AA        （耳机 → 手机）
```

| 字段 | 说明 |
|---|---|
| HEADER | `0xFF` = 命令，`0xDD` = 响应/通知 |
| SEQ | 滚动序号，命令侧递增，响应侧回显 |
| CMD/TYPE | 命令类型（见 §4）；对 SET 命令 = `0x02` |
| CHECKSUM | `(前序所有字节之和) & 0xFF` |
| 0xAA | 固定帧尾 |

```python
def build_frame(header: int, seq: int, cmd: int, payload: bytes) -> bytes:
    head = bytes([header, seq, cmd]) + payload
    ck = sum(head) & 0xFF
    return head + bytes([ck, 0xAA])
```

## 指令参考

### 查询全量状态 — 0x1E

```
格式:  ff XX 1E fa 01 [28 个参数 ID…] CK AA
```

载荷固定为 30 字节（`fa 01` 子命令头 + 28 个参数 ID），与 MK2 相同：

```
fa 01 07 08 09 0c 0d 0e 12 2a 2b 2c 2d 2e 2f 31 32 33 36 37 38 39 3a 3b 3c 3d 3f 45 46 49
```

**实测**（帧 1608）：

```
TX → ff 00 1e fa 01 07 08 09 0c 0d 0e 12 2a 2b 2c 2d 2e 2f 31 32 33 36 37 38 39 3a 3b 3c 3d 3f 45 46 49 e9 aa
RX ← dd 00 15 [TLV 状态数据…] 9a aa     （直接回 0x15，无 0x01 ACK）
```

### 设置参数 — 0x02

```
格式:  ff XX 02 [TYPE] [VALUE…] CK AA
```

**已确认的 TYPE：**

| TYPE | 功能 | 值 | 实测命令 |
|---|---|---|---|
| `0x09` | ANC 模式 | `01` 降噪 / `02` 普通 / `03` 通透 / `04` 风噪 | `ff 04 02 09 01 0f aa`（降噪） |
| `0x0E` | 游戏模式（效果 = 降延迟） | `01` 开 / `00` 关 | `ff 09 02 0e 01 19 aa`（开） |
| `0x2A`–`0x33` | 自定义 EQ 段位（9 段） | 段增益，观测值域 0–5 | `ff 08 02 2a 01 34 aa`（段 1 = 1） |

**响应**：i7 对 SET 直接回 `0x02` 回显（回显 type+value，SEQ 回显），**无 MK2 式的 `0x01` ACK**：

```
TX → ff 02 02 09 04 10 aa            （ANC = 风噪）
RX ← dd 02 02 09 04 ee aa            （回显）
RX ← dd 02 02 09 04 ee aa            （约 0.3s 后重复一次）
```

（实测每条 SET 收到两次相同回显：立即一次 + 约 0.3–0.5s 后重复一次。）

## 状态响应 TLV（0x15）

编码：`[LEN][TYPE][VALUE…]`，**LEN = 1 + 值长**（LEN 覆盖 TYPE + VALUE 字节），可嵌套。

**实测完整响应**（帧 1615，SEQ=00）：

```
dd 00 15
  01 01 00                                  ← 3 字节头（MK2 为 01 01 01）
  02 01 03                                  TLV 0x01 = 03（设备信息）
  02 04 08                                  TLV 0x04 = 08（设备信息）
  05 00 11 00 12 01                         TLV 0x00 = 11 00 12 01（能力位段）
  13 03 14 08 15 00 02 07 00 02 08 01
       02 09 01 04 0c 64 64 5b 04           TLV 0x03 = 嵌套块（见下）
  04 0d 03 00 03                            TLV 0x0D = 03 00 03
  02 0e 00                                  TLV 0x0E = 00（游戏模式关）
  02 12 01                                  TLV 0x12 = 01
  02 2a 01 02 2b 02 02 2c 05 02 2d 03
  02 2e 02 02 2f 04 02 31 01 02 32 01
  02 33 00                                  自定义 EQ 9 段 = 01 02 05 03 02 04 01 01 00
  05 36 01 01 00 00                         TLV 0x36 = 01 01 00 00
  02 45 01                                  TLV 0x45 = 01
  02 46 00                                  TLV 0x46 = 00
9a aa
```

嵌套块（TLV 0x03 的值，含子 TLV）：

```
14 08 15 00                                 ← 子块头（0x14 / 0x08 / 0x15 00）
02 07 00                                    TLV 0x07 = 00（左右耳子状态）
02 08 01                                    TLV 0x08 = 01
02 09 01                                    TLV 0x09 = 01（ANC = 降噪，镜像主块）
04 0c 64 64 5b                              TLV 0x0C = 64 64 5b（电量 100/100/91）
```

## 与 BudsFeel MK2 的差异

| 项 | MK2 | i7 |
|---|---|---|
| SET 响应 | `0x01` ACK（`dd XX 01 fe`）+ 0x0E 时额外 NOTIFY（seq=00） | 直接 `0x02` 回显（seq 回显，无 0x01 ACK） |
| 查询响应 | ACK + `0x15` STATUS | 直接 `0x15` STATUS |
| 状态 3 字节头 | `01 01 01` | `01 01 00` |
| 首个信息 TLV | `05:03` | `01:03` |
| `0x00` 块 | `11 01 12 04` | `11 00 12 01` |
| `0x0D` | `02 00 00` | `03 00 03` |
| EQ 组 | `2A` 双字节值 + `2B..2F` + `32`（≈8 段） | `2A..2F` + `31 32 33` = 9 段单字节 |
| `0x36` | `01 01 00 01` | `01 01 00 00` |
| `0x45`/`0x46` | 不返回 | `01` / `00` |
| 电量仓字节 | 哨兵值（`b9`/`ff`） | 真实电量（`5b` = 91） |
| SPP 鉴权 | 文档记录有（待复核） | 无，免鉴权直连 |

## 后续步骤

### 补抓计划（一次锁定全部未知）

按顺序操作，**每步之后发一次 `0x1E` 查询**，对比相邻状态响应哪个字段变化：

1. 切 4 个 EQ 预设各一次 → 锁定预设 SET type + 索引映射（当前选中项字段 = `45`/`46`/`0D`/`36` 之一）
2. 降噪深度 3 档 → 锁定深度 SET type（同时确认 `45`/`46`/`0D` 归属）
3. 通透强度 3 档 → 锁定强度 SET type
4. 查找耳机 左/右 各一次 → 捕获多字节 SET
5. （可选）自定义 EQ 拨两段 → 确认 `2A`–`33` 段位与增益值域

### 实现要点（相对 MK2 代码）

- 帧协议、校验和、查询载荷、TLV 编码与 `BudsFeelMk2CommandSet`/`BudsFeelMk2ResponseParser` 完全兼容，可复用；
- 游戏模式直接用 `0x0E`（与仓库 MK2 实现一致，**不要**照搬 MK2 文档旧版的"0x0E=低延迟"）；
- i7 无 `0x01` ACK，SET 回显为 `0x02`——现有 parser 的 `parseUnsolicitedNotification` 可直接解析；
- 自定义 EQ：9 段 `0x2A`–`0x33`，SET type = 段号、value = 增益；
- 降噪深度 / 通透强度 / EQ 预设 / 查找耳机：待补抓后填充。
